# MDX components

Beyond plain Markdown, Neuron ships live components you can drop straight into a note. They render in the preview pane.

## Badge

Badges take a `type` and `text`. The four types map to the app's semantic colors:

<Badge type="success" text="shipped" />
<Badge type="info" text="in review" />
<Badge type="warning" text="blocked" />
<Badge type="error" text="failing" />

## Callout

Callouts wrap a titled, colored block of text. Keep the body to a short sentence:

<Callout type="success" title="It saved">
Every keystroke is written to disk locally — there is no save button.
</Callout>
<Callout type="warning" title="Unclosed tags break the preview">
If you forget a closing tag, the preview shows a clear compilation error with a fix.
</Callout>

## DbView

Embed a `.db` database inline by `@path` from the workspace root. It stays live
— editing the database in its own tab updates the embed. Use `view` to pick
`table` (default), `board`, or `card`:

<DbView path="@Planner.db" table="tasks" view="board" />

The embed is read-only; open the `.db` file itself to edit rows and schema.

## Flashcard

A question you answer before you are shown the answer. The prompt is the
`front` attribute; everything inside is the answer, and it goes through the
Markdown parser like any other block:

<Flashcard front="Where does a note's full-width setting live, and why there?">
In the note's own **frontmatter**. It is a property of the file rather than an
app setting, so it travels with the note into any other editor.
</Flashcard>

The answer is not in the document until you ask for it, so you cannot read it by
scrolling past or by searching the page. Cards work the same way in Reading view
and in the Live editor.

The prompt is plain text — attributes are not parsed as Markdown, so backticks
and `**` appear literally there. Put anything that needs formatting in the
answer, which is parsed like any other block.
